## 🔬 What I tested / ran

- Diagnosed and fixed a critical train/benchmark event-leakage bug (issue #32) in the `phasenet-retrain` repo, affecting sharded datasets: **mlaapde**, **aq2009gm**, and **cwa**.
- Root cause: `trace_name` is not a unique key in sharded datasets — it's reused as a positional slot index across monthly/yearly metadata shards. The same `trace_name` refers to a *different real earthquake* per chunk. Overlap rates: **93.9% / 85.0% / 8.3%** of rows in mlaapde/aq2009gm/cwa share their `trace_name` with a row in another chunk.
- `event_keys.trace_key_map()` was using a plain `trace_name → key` dict, silently collapsing duplicates to whichever chunk loaded last — returning an arbitrary (usually wrong) event ID. This also undermined the earlier issue #7 train/val event-grouping fix for these same three datasets.
- Modified three files:
  - **`event_keys.py`**: `trace_key_map()` now keyed by `(trace_name, chunk)`, unioning (not overwriting) on residual collisions. Added `trace_key_map_any_chunk()` for `benchmark_manifest.csv`, which doesn't retain chunk identity for aq2009gm/cwa — deliberately conservative for that one-directional exclusion check.
  - **`build_training_dataset.py`**: `process_dataset()` now excludes training rows whose *event* (not just `trace_name`) matches a benchmark row, checked row-wise via `derive_event_keys()`. `assign_splits()` / `_event_group_ids()` now group by `(trace_name, chunk)`.
  - **`audit_event_leakage.py`**: Fixed a silent CSV dtype bug where `chunk` was reloading as `"201406.0"` instead of `"201406"`, which was causing the audit to falsely report **0% leakage everywhere** once chunk was added to the join key.

- Re-audited all previously deployed manifests (v1, v2, v3, tele2x, v18, p_focused, and the earlier eventclean rebuild) with the corrected methodology.

## ✅ Decisions made and why

- **Keyed `trace_key_map()` by `(trace_name, chunk)` rather than just `trace_name`**: Necessary to correctly distinguish the same positional slot index across different shards. Union (not overwrite) on collision handles the genuine cwa ambiguity without hiding it.
- **Added `trace_key_map_any_chunk()` as a separate function for benchmark manifest lookups**: `benchmark_manifest.csv` doesn't retain chunk identity for aq2009gm/cwa, so a chunk-agnostic lookup is needed there. Kept it deliberately conservative (any-chunk match = exclude) for the one-directional exclusion check — better to over-exclude training data than to silently include contaminated rows.
- **Excluded by event match (row-wise via `derive_event_keys()`), not trace_name match**: Ensures the exclusion logic is unaffected by the dict-collision bug — even if the map had residual issues, row-wise derivation is ground truth.
- **Gitignored `data/manifests_v2_bmfix`**: Verification artifact only; no need to commit rebuilt manifests until the full pipeline rerun is validated.
- **Accepted ~9.9% residual cwa leakage as an honest upper bound**: Attempting to resolve the source-data ambiguity would require external catalog information not available in the repo. Documenting it clearly in the commit message rather than papering over it.
